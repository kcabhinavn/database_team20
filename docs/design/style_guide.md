# Style guide

These rules keep every screen looking and behaving the same. All values live in [`tokens.css`](tokens.css), which is
generated by [`src/build_design.py`](src/build_design.py), and the web app imports that file instead of hard-coding colours.
To see everything rendered in the real palette, look at the [UI kit](ui_kit.svg).

**Principles**

1. **Consistency over sophistication.** A small set of components is reused on every screen.
2. **One primary action per view.** "Book trip" and "Refresh now" are the only filled teal buttons on their screens.
3. **The data is the loudest thing on the page.** Chrome stays grey and quiet.
4. **Every data region has a designed loading, empty and error state** (wireframe W09). No screen is ever left blank.
5. **Colour is never the only cue.** Badges carry text, amounts carry a +/− sign, and charts have labels and a table view.

The app has a **light theme only**. That is a scope decision; the assignment does not require a dark mode.

## Colour

| Token | Hex | Use | Contrast |
|---|---|---|---|
| `primary` | `#0F766E` | Primary button, focus ring, active nav, links | 5.47:1 on white |
| `primary-hover` | `#115E59` | Hover/pressed primary; text on `primary-soft` | 7.58:1 (white text) |
| `primary-soft` | `#CCFBF1` | Selected chip, highlighted row | 6.73:1 with `primary-hover` text |
| `text` | `#0F172A` | Body and headings | 17.8:1 |
| `text-muted` | `#475569` | Labels, helper text, table headers, secondary values | 7.58:1 |
| `text-placeholder` | `#64748B` | Input placeholders | 4.76:1 |
| `text-faint` | `#94A3B8` | **Disabled controls only**, never information | 2.56:1 (exempt) |
| `border` / `border-strong` | `#E2E8F0` / `#CBD5E1` | Card and table lines / input borders | n/a |
| `bg` / `surface` / `surface-muted` | `#F8FAFC` / `#FFFFFF` / `#F1F5F9` | Page / cards / table header, read-only field | n/a |
| `success` on `success-soft` | `#15803D` on `#DCFCE7` | COMPLETED, CREDIT, ACTIVE, PASSED, success alert | 4.57:1 |
| `warning` on `warning-soft` | `#B45309` on `#FEF3C7` | REQUESTED, concurrent-update alert | 4.51:1 |
| `danger` on `danger-soft` | `#B91C1C` on `#FEE2E2` | DEBIT, FAILED, booking errors, field errors | 5.30:1 |
| `info` on `info-soft` | `#1D4ED8` on `#DBEAFE` | IN TRANSIT, informational alerts | 5.49:1 |

All contrast ratios were measured with WCAG relative luminance, and every text pair clears AA (4.5:1).

**Meaning is fixed.** The same state always has the same colour on every screen:

| Thing | Badge / text |
|---|---|
| Trip `REQUESTED` → `IN_TRANSIT` → `COMPLETED` | warning → info → success (shown as "IN TRANSIT", with a space) |
| Wallet `CREDIT` / `DEBIT` | success / danger badges; amounts `+$60.00` (green) and `−$24.50` (red), always with the sign |
| Vehicle active / inactive | success badge "ACTIVE" / neutral badge "INACTIVE" |
| Inspection passed / failed | success "PASSED" / danger "FAILED" |
| Something new since the last refresh (audit row, map vehicle) | solid teal "NEW" for one refresh cycle |

### Chart colours

Charts use a separate, validated palette so a series never looks like a status:

| Token | Hex | Used for |
|---|---|---|
| `chart-series-1` | `#2a78d6` | Daily revenue bars, top-tag bars, map vehicle markers |
| `chart-series-2` | `#eb6834` | 7-day moving average line, map origin pin |
| `chart-ordinal-1…5` | `#86b6ef` → `#104281` | Rating distribution 1★ (lightest) → 5★ (darkest) |
| `chart-grid` / `chart-axis` | `#E2E8F0` / `#CBD5E1` | Gridlines / baseline |

These come from the dataviz skill's reference palette, and we checked them with its validator against our white surface.
The series pair passes the lightness, chroma, colour-blind separation (worst ΔE 24.7) and contrast checks. The rating ramp
passes the ordinal checks (monotone lightness, a visible step between shades, and its lightest end at 2.11:1).

**Chart rules**

- One y-axis per chart. Revenue bars and the moving-average line are both in $, so they share it.
- Show a legend whenever there are two or more series. A single series gets no legend; its title names it.
- Values and labels use text colours, never the series colour.
- Every bar and point has a hover tooltip, and line charts get a crosshair. On touch screens, a tap opens the tooltip.
- Every chart has a "View as table" toggle.
- Status colours are never used as chart series.
- Axes start at 0, even when that makes the top-tags bars look almost identical. That is true of the seed data.

## Typography

**Inter** (Google Fonts: 400, 500, 600, 700), falling back to `system-ui`. **JetBrains Mono** is used only for IDs, routes
and the technical details line.

| Role | Size / weight | Example |
|---|---|---|
| Page title | 20 / 700 | "Book a trip" |
| Section / card title | 16 (cards 15) / 700 | "Revenue ranking" |
| Body, table cells | 14 (cells 13) / 400 | rider names, fares |
| Labels, captions, table headers | 12 / 600, headers uppercase with +0.4 letter-spacing | "BALANCE AFTER" |
| KPI value | 24 / 700 | `$16,801.83` |
| Hero number | 40 / 800 | average rating `4.01` |
| IDs | mono 12 / 400, `text-muted` | `f35d765d…` |

Table columns and money columns use `font-variant-numeric: tabular-nums` and are right-aligned. Stand-alone KPI numbers
use normal figures.

## Spacing, shape, layout

- **Spacing:** a 4 px grid (4, 8, 12, 16, 24, 32, 48). Cards have 16 px padding and a 16 px gap between them; page gutters
  are 24 px.
- **Radius:** 6 px for controls, 8 px for cards, tables and alerts, and pill shape for badges and chips.
- **Elevation:** cards use a 1 px border and a faint shadow. Only overlays (combobox list, tooltip) get the bigger shadow.
- **Controls:** 36 px tall on desktop and at least 44 px on touch screens.
- **Layout:** a 216 px sidebar, a 56 px top bar, and content up to 1200 px wide on a 12-column grid.
- **Breakpoints:** from 1024 px, two-column layouts. From 768 px, one column. Below 768 px, the sidebar becomes a drawer.
  Below 640 px, tables become cards (W10).

## Components

This is the whole set. If a screen seems to need something else, change one of these instead of adding a new one.

| Component | Variants and states | Where |
|---|---|---|
| **Button** | primary / secondary / ghost; hover, focus ring, disabled, busy (spinner, disabled, label "Booking…") | everywhere |
| **TextField / MoneyField** | label above, helper below, error replaces the helper; `$` prefix and 2 dp for money; read-only | Book a trip |
| **Combobox** (async) | server-side search, 300 ms debounce, keyboard navigation, "no results", disabled options ("Out of service") | rider, vehicle, wallet-rider pickers |
| **DateRange** | preset chips (7 d / 30 d / 90 d / All) plus a custom range | Trips, Wallet audit, Analytics |
| **SegmentedControl** | 2–3 options, one selected | View as, review scope |
| **Chip** | filter (selectable), tag (static, optional count), removable (✕) | filters, tags, features |
| **Badge** | the status colours above, always with text | tables, detail pages |
| **Card** | title, subtitle, actions slot. **Each card owns its data request and its own loading/empty/error state** | all pages |
| **StatCard** | label, value, sub-line (often an "as of" time) | Overview, Vehicle detail, Wallet audit |
| **DataTable + Pagination** | sortable header, row click, highlighted row, skeleton rows, empty slot; server-side paging; becomes a card list on phones | Browse, Audit, Ranking |
| **Alert** | success / error / warning / info; title, body, actions, collapsible technical details | booking result, errors |
| **Stepper** | trip status REQUESTED → IN TRANSIT → COMPLETED, with the current step ringed | Book a trip, Trip detail |
| **StateView** | loading (skeleton after 150 ms), empty (message + one action), error (message + Retry + details) | wraps every data region |
| **Chart** | bar + line, horizontal bars; legend, tooltip, table toggle | Overview, Reviews |
| **MapView** | origin pin, 5 km radius ring, numbered vehicle markers, NEW ring; the list beside it is the accessible equivalent | Find a vehicle / Live map |

## Formatting

| Value | Format | Example |
|---|---|---|
| Money | `$` with 2 dp and thousands separators; negative values use a true minus sign | `$2,275.44`, `−$24.50`, `+$60.00` |
| Large totals in KPIs | whole dollars, exact value in the tooltip | `$6,322,471` |
| Date-time | local time, day month year, 24 h; UTC on hover | `09 Oct 2026, 09:12` |
| Live data | relative time, updated every second | `updated 3 s ago`, `ping 1 min ago` |
| UUIDs | first 8 characters + `…`, monospace, with a copy button on detail pages | `f35d765d…` |
| Distance | km with 2 dp | `0.31 km` |
| Rating | 1 dp in KPIs, 2 dp in the hero number, with ★ | `4.12 ★` |
| Vehicle | plate, then class in muted text | `RS00409 · POOL` |

## Messages

Tone: plain words, no error codes in the headline, say what happened and what to do next, and **always say whether money
moved**. The raw database text goes in a collapsed "Technical details" line.

| `p_status` from `sp_atomic_booking` | Title | Body | Action |
|---|---|---|---|
| `COMMITTED` | Trip booked: $X paid from your wallet | Trip … is REQUESTED with vehicle … | View trip |
| `…insufficient wallet balance` | Not enough money in your wallet | This trip costs $X but your balance is $Y. Nothing was charged. | Change fare |
| `…rider already has an active trip` | You already have a trip in progress | A rider can have only one requested or in-transit trip at a time. Nothing was charged. | View active trip · Mark it completed |
| `…vehicle … is not active` | This vehicle is out of service | RSxxxxx is not active right now. Choose another vehicle. | Choose vehicle |
| `…rider/vehicle … not found` | We couldn't find that rider or vehicle | It may have been removed. Refresh and try again. Nothing was charged. | Refresh |
| `…fare must be greater than 0.00` | (inline on the Fare field) | Enter an amount greater than $0.00. | none |
| `…concurrent update, retry` | Your wallet changed at the same moment | Another update happened at the same time. Nothing was charged. Please try again. | Try again |
| network error or HTTP 5xx | Couldn't book the trip | The server didn't respond. We don't know if it went through, so check My trips before trying again. | Check My trips · Retry |

Empty states name what is empty and offer one action. For example, "No trips match these filters" with **Clear filters**,
or "No available vehicles within 5 km of this point" with **Simulate pings**.

## Accessibility checklist

- Text contrast is at least 4.5:1 (see the table above) and focus is always visible (`--rs-focus-ring`).
- Every control is keyboard-reachable. Comboboxes follow the ARIA combobox pattern, and table rows open with Enter.
- Booking results, errors and map updates are announced with `aria-live="polite"`.
- The map has an equivalent list, and every chart has a table view.
- Touch targets are at least 44 px, and nothing is shown only on hover.
